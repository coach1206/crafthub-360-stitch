# Known Limitations — Production Package 5

1. **No live external monitoring/alerting accounts.** Sentry, UptimeRobot/BetterStack, PagerDuty, Slack webhook delivery, Stripe dashboard/webhook live delivery, and any managed DB/object-storage provider dashboard were not exercised. All adapters/config/threshold logic are real and locally tested; live delivery is a credential/config task for whoever provisions the eventual paid accounts.
2. **In-app metrics are in-memory only.** `server/lib/metrics.mjs` resets on process restart. Sufficient for MVP per the mandate's "simplest compatible approach" instruction; a managed metrics backend is a future upgrade, not built this pass.
3. **No live object-storage bucket** — versioning, lifecycle policy, replication, and media-asset checksum verification are documented as a plan (`object-storage-protection.md`) but not exercised against a real R2/S3 bucket.
4. **No WAL-based point-in-time recovery** — the local unmanaged Postgres instance has no WAL archiving; only full-dump restore (to the last backup point) was proven. PITR requires a managed provider.
5. **Pre-migration backup is not yet auto-invoked** from `runMigrations.js` — the `--pre-migration` flag exists on `scripts/backup-smokecraft-database.mjs` but must currently be run manually before a migration. Recommended follow-up: wire it into the migration runner.
6. **Passport known issue carried forward** (not fixed this pass, by design — see `passport-known-issue.md`): `verify-passport-security-unified-identity.mjs`'s legacy client-trusting stamp-claim technique no longer matches the current, more secure server-computed-eligibility contract. Confirmed pre-existing and non-customer-impacting; recommended for Package 7 to either rewrite the script's technique or formally retire it.
7. **E.A.T. static-source-inspection script (`verifyPhaseF7EATSmokeCraftLiveSync.js`) has 37 pre-existing failures**, confirmed identical before and after this pass's changes (via `git stash` comparison). Not investigated further — out of this package's scope (it is a source-pattern-matching test, not a live-behavior test, and Package 5's mandate does not ask for E.A.T. feature work).
8. **No live public status page built** — plan only (`status-page.md`); a reasonable Package 6/7 candidate.
9. **`final-acceptance.mjs`'s visual-regression baseline diffs (67 passed/16 failed)** were observed this pass but are a pre-existing, separate visual-pixel-diff suite outside this package's required regression list; not investigated to stay in scope (documented, not hidden).
10. **Backup/restore proven locally only.** The 20/20 real restore-validator result is against a real local Postgres instance in this sandbox — it has not been run against a live managed-provider Postgres instance (Railway/Render/RDS/Neon), which may have provider-specific restore mechanics (e.g. different `pg_restore` flags, IAM-gated access) not exercised here.
11. **RBAC test used dev-mode header-based identity** (`x-novee-user-role` etc.), which is explicitly and unconditionally blocked in `NODE_ENV=production` (verified pre-existing behavior in `authMiddleware.js`). The RBAC gates themselves (`requireAuth`/`requireManager`/`requireAdmin`) are the same code path used in production; only the *test's* method of establishing identity is dev-only.
