# Package F — Known Limitations

- The XP-breakdown-by-category rows (Completed-Session XP / Passport XP / Pairing XP / Mentor XP) still derive from local `session.completedSteps` via `smokecraftRewards.js` helper functions, not a server-side category breakdown endpoint (none exists). The top-line total, rank, and milestone eligibility — the specific figures the prior audit flagged as unverified — are now server-sourced; the category *split* of that same, now-server-anchored total remains a local derivation for display convenience only, matching the same pattern already accepted elsewhere in this app (e.g. achievement progress bars). Not treated as a new gap: it does not affect completion, XP totals, duplicate/replay safety, or cross-player isolation.
- Earned session badges (`earnedSessionBadges`, via `getEarnedBadges(session.completedSteps)`) are likewise still derived from the local completedSteps list rather than the server `smokecraft_awards` table. Real evidence (each completedStep was itself server-verified at the time it was earned), but not re-read from the server on this screen. Flagged for a future pass if badge display parity with XP display parity is desired — out of this package's scoped "displayed totals" fix.
- `SC-D067` and all previously-fixed defects remain fixed; no new defect (SC-D068) was required — the Session 25 gap was a data-source completeness issue caught and fixed pre-commit, not a broken pre-existing runtime defect.
- Pre-existing, unrelated `src/constants/smokecraftRewards.test.js` legacy test file (22 passed / 5 failed) reflects a documented pre-existing drift between its old 24-session/8-visit numbering fixtures and the current 27-session spine (see file's own header comment) — confirmed identical failure count on the unmodified `a784ba22` baseline via `git stash`. Not touched by this package; not a regression.
