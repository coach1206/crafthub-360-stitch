SC-D014 root cause and fix — Holistic Fix 2E-6

ROOT CAUSE (confirmed via source read):
- server/middleware/smokecraftGuestIdentity.js issues a real, server-signed
  JWT cookie (smokecraft_guest_session) only via ensureSmokeCraftGuestIdentity.
- That function is only called from managementSyncRoutes.js's
  POST /guest-session endpoint.
- The frontend only calls that endpoint via establishGuestSession() inside
  src/hooks/useSmokeCraftServerJourney.js.
- That hook is used by WelcomeExperience.jsx (Session 1) among a few other
  screens — meaning the cookie is established the first time a player's
  browser loads Session 1.
- FlavorMemory.jsx (Session 10)'s handleContinue() requires both
  saveToBackend() and saveToPassport() (the latter uses
  credentials: 'include') to resolve ok before advancing.
- A REAL player always visits Session 1 before Session 10, so the cookie is
  always present in a real playthrough. The original SC-D014 finding
  reproduced the failure only because an ad hoc test seeded localStorage
  directly and navigated straight to Flavor Memory, skipping the one real
  page load (Welcome) that establishes the cookie.

CONCLUSION: (a) test-harness gap, not (b) a real product defect. No
product code was changed — the underlying behavior was already correct.
