# SmokeCraft 360 — Owner Visual Audit (Inspection Only)

**Purpose**: a real, currently-rendered, numbered walkthrough of the canonical player sequence, captured via genuine browser navigation/clicks (no force-clicks, no fake state, no substitute or model-generated imagery), for owner review. **No production code was changed to produce this audit.**

- Capture viewport: 1440×900 (desktop), single consistent viewport for the master board.
- Total screens captured: **30**, numbered **001–030**.
- Individual screenshots: `public/proof/smokecraft-owner-visual-audit/0NN-slug.png`
- Raw capture manifest: `public/proof/smokecraft-owner-visual-audit/sequence-manifest.json`
- Master contact sheets: `public/proof/smokecraft-owner-visual-audit/SMOKECRAFT_FULL_GAME_VISUAL_AUDIT_01.png` / `_02.png` / `_03.png` (12/12/6 thumbnails; 3 sheets because 30 thumbnails at a legible size don't fit one readable image)

Flag vocabulary used below is restricted to the 14 approved values: VISUALLY_COMPLETE, BLANK_CONTENT, EMPTY_PANEL, MISSING_IMAGE, BROKEN_IMAGE, WRONG_IMAGE, WRONG_ASSET_MAPPING, UNAPPROVED_ASSET, STATIC_SHELL, CONTENT_COVERED, CONTROL_COVERED, UNREACHABLE_CONTINUE, OUT_OF_SEQUENCE, LOW_CONFIDENCE_SEQUENCE.

Asset trace: content on nearly every canonical gameplay screen is real live DOM (text/controls), not a baked image — per `src/constants/smokecraftAssets.js` these screens only use a decorative hero/background image (e.g. `humidorMatchHero`, cropped stock photography, or a `REF`/`RAW` GitHub-hosted key) behind real DOM content. Where a screen's decorative image traces to a named key in `smokecraftAssets.js`, that key is listed; where a screen renders no identifiable `SC_ASSETS` key (plain CSS background or none), it's noted as N/A — decorative only, not a defect.
